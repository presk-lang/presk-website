Presk

A language for neural networks with an exact meaning, compiled under a declared error budget.

What it is

A Presk program denotes a mathematical function over tensors of real numbers. The language has no machine number type for its tensors: no float32, no bfloat16. Shapes, with named and symbolic axes, are part of the types and are checked before anything runs; every function carries a regularity class that decides whether it may be differentiated; randomness is an explicit effect.

Precision is a compilation choice. The author declares an error budget on a result, and the compiler chooses, site by site, the machine types and the order of operations that meet it, then checks the choice by measurement against an exact reference. A rewrite the optimizer applies changes nothing over the reals; an approximation is always declared, and bounded.

Training and inference are derived from the same program, not written twice. The compiler is written in Rust and generates native code.

An example

module LayerNorm{D : dim} {
  param γ : ℝ[D]  init = ones     -- gain
  param β : ℝ[D]  init = zeros    -- bias

  -- eps is not a numerical guard: the semantics is exact. It is a
  -- hyperparameter of the model. The stability of sqrt and of the
  -- division is the compiler's, under the budget.
  fn apply(x : ℝ[..., model: D], eps : f64 = 1e-5) -> ℝ[..., model: D] =
    let μ  = mean(axis model, x)
    let σ2 = mean(axis model, (x - μ)^2)
    let x̂  = (x - μ) / sqrt(σ2 + real(eps))
    x̂ * γ + β
}

A layer norm over a symbolic model dimension D, checked once for every D: one of the programs of the specification's examples, which the compiler checks as its test suite.

What the type checker says of it: the shape of every value, the regularity of each function in each of its arguments, and the effects it uses. A budget comes next (presk calibrate, presk solve); the manual's tutorial walks through it.

Where it stands

Presk is a research project at Mines Paris – PSL, funded by the french research program PEPR CAMELIA (composants matériels et logiciels pour l'IA). The compiler exists with a reference interpreter that computes the exact meaning of a program, a native backend with its own code generator and a second one through clang, training and serving, an optimizer over exact rewrites, a solver for error budgets, exports to PyTorch and to C, and one compilation drawn as a document with every decision and its reason. It has been tested on statements fixed in advance, and the ones that fail are recorded as failing:

  • A budget declared on a training step's update buys a step 1.75 times faster than computing everything in double precision, at the scale of a course's GPT, level with single precision, the error measured against the exact reference. A budget on the loss alone buys no time: it leaves the gradient and the optimizer, most of a step, out of reach.
  • The compiler's own code generator is at the C compiler on its kernels — 0.99 times the exported C program's training step, 0.87 with the backend through clang — and the C program takes 0.93 times PyTorch eager's step and 1.7 times compiled PyTorch's, every bit of its arithmetic the same as the native backend's.
  • A static cost model of the loop nests, frozen before the measurements, ranks the fastest arrangements of an attention kernel as measurement does on 91.7 to 92.7 % of close comparisons on another kind of core, and on 85 to 89 % on new shapes, short of the 90 % set for it. Used as a filter, it finds an arrangement within 1.05 times the best for under 2 % of the cost of timing every one.
  • Llama 3.2 1B, on its published weights, was solved whole under a budget read off a quality target: at most one of the exact model's decisions in a hundred may change. The solver returned the checkpoint's own 16-bit weights with 32-bit arithmetic and a dozen stored values in 16-bit; on 1 024 held-out decisions it changes none, and its error is under the budget. llama.cpp's 16-bit run changes none either, and transformers' 16-bit run changes 32, but neither stays within the budget: the guarantee bounds the worst error anywhere, not only where a decision is close. For the same reason the compiler does not beat the 8-bit recipes on weight bytes — their errors are 37 to 43 times the budget while they change 2.7 % of the decisions —, which was stated as a hypothesis and fails.
  • The GPU has not started, and serving recomputes the whole context at every word.

Install

cargo install presk
presk --help

A Rust toolchain (1.85 or later), m4 and a C compiler: the reference interpreter uses GMP and MPFR, built once from their sources. The C export's programs need only a C11 compiler. PyTorch is not needed, except to run the conformance tests the export generates.
