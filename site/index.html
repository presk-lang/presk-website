Presk

A language for neural networks with an exact meaning, compiled under a declared error budget.

What it is

A Presk program denotes a mathematical function over tensors of real numbers. The language has no machine number type for tensors: no float32, no bfloat16. Shapes, with named and symbolic axes, are part of the types and are checked before anything runs; every function carries a regularity class that determines whether it may be differentiated; randomness is an explicit effect.

Precision is a compilation choice. The author declares an error budget on a result, and the compiler chooses, site by site, the machine types and the order of operations that meet it, then checks that choice by measurement against an exact reference. Every rewrite the optimizer applies is exact over the reals; any approximation is declared and bounded.

Training and inference are derived from the same program, not written twice. The compiler is written in Rust and generates native code.

An example

module LayerNorm{D : dim} {
  param γ : ℝ[D]  init = ones     -- gain
  param β : ℝ[D]  init = zeros    -- bias

  -- eps is not a numerical guard: the semantics is exact. It is a
  -- hyperparameter of the model. The stability of sqrt and of the
  -- division is the compiler's, under the budget.
  fn apply(x : ℝ[..., model: D], eps : f64 = 1e-5) -> ℝ[..., model: D] =
    let μ  = mean(axis model, x)
    let σ2 = mean(axis model, (x - μ)^2)
    let x̂  = (x - μ) / sqrt(σ2 + real(eps))
    x̂ * γ + β
}

Layer normalization over a symbolic model dimension D, checked once for every value of D. It is one of the specification's example programs, which the compiler uses as its test suite.

What the type checker reports: the shape of every value, the regularity of each function in each of its arguments, and the effects each function uses. Declaring a budget comes next (presk calibrate, presk solve); the manual's tutorial walks through it.

A whole network

The pipeline view of a small GPT is the document the compiler writes about one compilation (presk explain), published here as version 0.17.1 wrote it. The program is a GPT in 127 lines of Presk, with two blocks and a model dimension of 64, on trained weights. What is compiled is its logits, under an error budget of 4.67·10−4 relative to the output.

The page follows the program through every stage, from the source to the kernels and the exported C program, and gives every decision with its reason. The solver puts 19 of the 25 values the program stores and 9 of its 21 parameters in single precision, and leaves the others in double precision; the error measured against the exact reference is 2.2·10−6, for a budget of 2.4·10−3 in absolute terms. A second tab draws the network as boxes and arrows, read from the same program.

The page is one file of 1.5 MB that carries its own scripts and fonts and loads nothing else. The files it names beside it (the listings, the C program) are not published here; the same command writes them.

Where it stands

Presk is a research project at Mines Paris – PSL, funded by the French research programme PEPR CAMELIA (composants matériels et logiciels pour l'IA: hardware and software components for AI). The compiler has a reference interpreter that computes the exact meaning of a program, a native backend with its own code generator and a second backend through clang, training and serving, an optimizer that applies only exact rewrites, a solver for error budgets, exports to PyTorch and to C, and a view of a compilation as a document that gives every decision and its reason. It has been tested against statements fixed in advance, and those that fail are reported as failing:

  • On a course-sized GPT, a budget declared on the update of a training step makes the step 1.75 times faster than computing everything in double precision, matching single precision, with the error measured against the exact reference. A budget on the loss alone buys no time: it leaves the gradient and the optimizer, which make up most of a step, out of reach.
  • On its own kernels, the compiler's code generator is on par with the C compiler: its training step takes 0.99 times as long as the exported C program's, and 0.87 times as long with the backend through clang. The C program's step takes 0.93 times as long as PyTorch's in eager mode and 1.7 times as long as compiled PyTorch's, with every bit of its arithmetic the same as the native backend's.
  • A static cost model of loop nests, frozen before the measurements, orders the fastest arrangements of an attention kernel as measurement does in 91.7 to 92.7 % of close comparisons on another kind of core, but in only 85 to 89 % on new shapes, short of the 90 % target set for it. Used as a filter, it finds an arrangement within 1.05 times the best at under 2 % of the cost of timing them all.
  • The solver was run on the whole of Llama 3.2 1B, with its published weights, under a budget derived from a quality target: at most one in a hundred of the exact model's decisions may change. It returned the checkpoint's own 16-bit weights, with 32-bit arithmetic and a dozen stored values in 16 bits; on 1 024 held-out decisions the result changes none, and its error is under the budget. llama.cpp's 16-bit run changes none either, and transformers' 16-bit run changes 32, but neither stays within the budget: the guarantee bounds the worst error anywhere, not only where a decision is close. For the same reason, the hypothesis stated in advance that the compiler would beat the 8-bit recipes on weight bytes fails: their errors are 37 to 43 times the budget, while they change 2.7 % of the decisions.
  • Work on GPUs has not started, and serving recomputes the whole context for every new word.

Install

cargo install presk
presk --help

Building it needs a Rust toolchain (1.85 or later), m4 and a C compiler: the reference interpreter uses GMP and MPFR, which are built once from source. Programs exported to C need only a C11 compiler. PyTorch is needed only to run the conformance tests that the PyTorch export generates.

Source

The compiler is published under the Apache License 2.0 at github.com/presk-lang/presk: the whole compiler at version 0.17.1, with one commit per version since 0.1.0. It includes the specification's example programs, which serve as its test suite (tests/examples), the tutorial's programs, BERT-large and Llama written in Presk, and the scripts behind every measurement. The specification's own repository will follow.
